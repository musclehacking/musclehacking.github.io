# Secret operations

Store newsletter values as Cloudflare Worker secrets or protected build variables. Never commit, print, persist in shell profiles, or copy them into screenshots or logs.

Required names are `TURNSTILE_SECRET_KEY`, `GETRESPONSE_API_KEY`, and `GETRESPONSE_CAMPAIGN_ID` (see `documents/architecture/newsletter.md`). The Turnstile secret lives in the macOS Keychain service `musclehacking-turnstile-secret`. Set `NEWSLETTER_ALLOWED_ORIGIN` only on preview to the deployed review origin, `https://musclehacking-astro-preview.webpop.workers.dev`. Version-preview hosts have a separate Cloudflare cross-site POST restriction and are not the form acceptance target.

Before setting any secret, verify the exact Cloudflare account, Worker, latest uploaded version, and active deployment. `wrangler versions secret bulk` reads JSON from stdin and creates a new version from the latest uploaded version; it does not deploy it. Confirm that the latest version is the intended tested build, verify the resulting code ETag/assets/bindings, then deploy only that returned version to the review Worker. Normal `wrangler secret put` can deploy immediately and must not be used as a non-promoting operation.

The GetResponse API key is recoverable from the WPX configuration through the approved wrapper and connection in `documents/migration/wpx-newsletter-discovery.md`. Keep its content out of command arguments, tool output, retained downloads, and logs. OpenSSH requires a seekable local download target; use a private mode-0600 temporary file outside Git, read it in memory, overwrite its contents with a redacted marker, and Trash the sanitised file before proceeding. Pass the extracted key to Wrangler through stdin; load Cloudflare credentials only into that command's environment.

Normally preview and production use separate subscriber destinations. That approval does not permit arbitrary contacts, list-setting changes, deletion, or production website tests. The complete approved address remains in the chat rather than committed records. The review Worker now holds the GetResponse values as secrets; production configuration remains unset.
